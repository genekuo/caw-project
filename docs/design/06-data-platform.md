## 1. Purpose and scope

This doc covers everything stateful plus the GitOps layout that deploys the whole platform.

**Responsibilities**

- PostgreSQL (CloudNativePG) with databases `inventory` and `keycloak`.
- MongoDB replica set (Percona Operator) with database `users`.
- RabbitMQ cluster (Cluster Operator + Messaging Topology Operator) with vhost, users, exchange and DLX.
- Two standalone Redis instances, `redis-sessions` and `redis-cache`.
- S3‑compatible object storage with bucket `bookstore-covers`.
- Backups for every stateful component.
- Namespaces, NetworkPolicies, External Secrets, Argo CD applications and sync order.
- Exporters, ServiceMonitors and alert rules for the data tier.

**Non‑goals (v1):** Redis HA, multi‑region, managed AWS services (phase 2, ARCH §6.1), a connection pooler for PostgreSQL.

## 3. PostgreSQL

### 3.1 Cluster

```yaml
apiVersion: postgresql.cnpg.io/v1
kind: Cluster
metadata: { name: pg-main, namespace: bookstore-data }
spec:
  instances: 3
  imageName: ghcr.io/cloudnative-pg/postgresql:17      # P-03
  storage: { storageClass: ${STORAGE_CLASS_FAST}, size: 20Gi }
  walStorage: { storageClass: ${STORAGE_CLASS_FAST}, size: 10Gi }
  postgresql:
    parameters:
      max_connections: "200"
      shared_buffers: "512MB"
      log_min_duration_statement: "500ms"
  bootstrap:
    initdb:
      database: inventory
      owner: inventory_app
      encoding: UTF8
      localeProvider: icu
      icuLocale: und
      localeCType: en_US.UTF-8   # Unicode-aware LC_CTYPE for pg_trgm; verify with show_trgm('哈利波特'), see ADR 0008
      secret: { name: pg-inventory-app }
  managed:
    roles:
      - name: keycloak
        login: true
        passwordSecret: { name: pg-keycloak }
  monitoring: { enablePodMonitor: true }
  affinity: { enablePodAntiAffinity: true, topologyKey: kubernetes.io/hostname }
  resources:
    requests: { cpu: "1", memory: 2Gi }
    limits:   { memory: 2Gi }
```

Second database via the `Database` CRD:

```yaml
apiVersion: postgresql.cnpg.io/v1
kind: Database
metadata: { name: keycloak, namespace: bookstore-data }
spec: { cluster: { name: pg-main }, name: keycloak, owner: keycloak }
```

### 3.2 Notes

- **A Unicode‑aware `LC_CTYPE` is required** for inventory search: `pg_trgm` classifies characters with the libc ctype, even when ICU is the locale provider, and ignores CJK characters under `C` (02 §5.3, [ADR 0008](../adr/261020-keep-pg-trgm-and-fts-for-search.md)). Set `localeCType` explicitly at `initdb` together with the ICU settings; changing it later means dump and restore. Verify on the bootstrapped cluster: `show lc_ctype` and `select show_trgm('哈利波特')` must return CJK trigrams.
- `pg_trgm` is created by inventory's Flyway migration (trusted extension; no superuser).
- Services connect to `pg-main-rw` (primary). No read replicas used by apps in v1.
- `inventory_app` and `keycloak` cannot connect to each other's database: `REVOKE CONNECT ON DATABASE … FROM PUBLIC` for both, granted only to the owner (run in a `postInitApplicationSQL` / a one‑time Job).
- Secrets `pg-inventory-app` and `pg-keycloak` are generated by ESO from Vault, not by CNPG, so they can be mirrored into `bookstore-app` and `identity` namespaces (P‑04).

### 3.3 Backups

- Barman Cloud plugin to an **off‑cluster** S3‑compatible bucket (`pg-backups`), not the in‑cluster covers store (same failure domain) (P‑05).
- Continuous WAL archiving; `ScheduledBackup` daily at 01:00; retention 30 days.
- Target RPO ≤ 5 min, RTO ≤ 1 h (P‑06). Restore drill quarterly: restore into a new cluster from the latest backup and run inventory's smoke tests against it.

## 4. MongoDB

`PerconaServerMongoDB` CR `users` in `bookstore-data`:

- Replica set `rs0`, 3 members, anti‑affinity by host, storage 10Gi on `${STORAGE_CLASS_FAST}`.
- Sharding disabled. TLS inside the cluster per operator defaults (P‑07).
- Users (created by a one‑time Job or the operator's user management):
  - `user-svc` on database `users` with a custom role: `find`, `insert`, `update` on `profiles`; `find`, `insert` on `audit_log`; `createCollection`, `createIndex`, `collMod` on `users` (for the startup validator and indexes, 03 §4).
- Backups: PBM to the off‑cluster backup bucket; daily snapshot at 01:30, PITR oplog on, retention 30 days.
- Connection string in Secret `mongo-user-svc` (key `uri`), mirrored to `bookstore-app`.
- ARCH warns against DocumentDB on AWS; keep that note in the `aws` overlay README.

## 5. RabbitMQ

### 5.1 Cluster

```yaml
apiVersion: rabbitmq.com/v1beta1
kind: RabbitmqCluster
metadata: { name: rabbitmq, namespace: bookstore-data }
spec:
  replicas: 3
  image: rabbitmq:4.1-management        # P-08
  persistence: { storageClassName: ${STORAGE_CLASS_FAST}, storage: 10Gi }
  resources:
    requests: { cpu: 500m, memory: 1Gi }
    limits:   { memory: 1Gi }
  rabbitmq:
    additionalPlugins: [rabbitmq_prometheus]
    additionalConfig: |
      default_queue_type = quorum
      vm_memory_high_watermark.relative = 0.6
      disk_free_limit.absolute = 2GB
      cluster_partition_handling = pause_minority
  affinity: { podAntiAffinity: … }       # one node per replica
```

### 5.2 Topology (Messaging Topology Operator CRs)

| Kind | Name | Spec |
| --- | --- | --- |
| `Vhost` | `bookstore` | `defaultQueueType: quorum` |
| `User` | `inventory` | credentials from Secret `rabbitmq-inventory` |
| `Permission` | `inventory@bookstore` | configure `^catalog\.sse\..*$`, write `^(catalog\.events|catalog\.sse\..*)$`, read `^(catalog\.events|catalog\.sse\..*)$` |
| `Exchange` | `catalog.events` | topic, durable |
| `Exchange` | `catalog.events.dlx` | topic, durable |
| `Policy` | `catalog-durable-dlx` | pattern `^catalog\.(?!sse\.).+$`, apply‑to `queues`, definition `{ "dead-letter-exchange": "catalog.events.dlx", "delivery-limit": 5 }` |

The inventory app declares its own exclusive SSE queues and bindings (02 §5.6), hence the configure permission limited to `catalog.sse.*`. It does not declare exchanges (no configure permission on `catalog.events`); the Topology Operator owns them.

Future durable consumers (`catalog.<consumer>`, quorum) and their DLQs (`catalog.<consumer>.dlq` bound to the DLX) are declared as `Queue` + `Binding` CRs in this chart when a consumer is added.

## 6. Redis

Two independent StatefulSets from one small in‑repo chart (`platform/charts/redis-standalone`), installed twice with different values. Avoid third‑party charts whose image distribution terms changed (P‑09).

| Value | `redis-sessions` | `redis-cache` |
| --- | --- | --- |
| Image | `valkey/valkey:8` (official Valkey image, minor pinned in overlays) | same |
| Replicas | 1 | 1 |
| `maxmemory` | 512mb | 1gb |
| `maxmemory-policy` | `noeviction` | `allkeys-lru` |
| Persistence | `appendonly yes`, `appendfsync everysec`, PVC 2Gi | `appendonly no`, `save ""`, `emptyDir` |
| ACL users | `default` off; `gateway` with `~bookstore:session:* +@all -@dangerous` | `default` off; `inventory` with `~inventory:* +@all -@dangerous` |
| Resources | req 100m/640Mi, limit 640Mi | req 100m/1200Mi, limit 1200Mi |
| Exporter | `oliver006/redis_exporter` sidecar | same |
| Network access | gateway pods only | inventory pods only |

- ACL file rendered from a Secret (passwords from ESO), mounted at `/etc/redis/users.acl`.
- `protected-mode yes`, `rename-command` not used (ACLs instead). `-@dangerous` blocks `FLUSHALL`, `KEYS`, `CONFIG` and similar; `SCAN` (used for cache eviction by prefix, 02 §5.4) is not in that category. Because `CONFIG` is blocked, the gateway must not let Spring Session try to configure keyspace notifications: use the default (non‑indexed) reactive session repository and, if any configuration action is attempted, register `ConfigureReactiveRedisAction.NO_OP`.
- Licensing: the instances run **Valkey 8** (BSD‑3, Linux Foundation), a protocol‑compatible fork of Redis 7.2.4, so the Redis 8 licence review (ARCH §6.3) is no longer needed ([ADR 0017](../adr/261020-use-valkey-for-sessions-and-cache.md), supersedes ADR 0009). Instance names, ACL users and `REDIS_*` env vars are unchanged; the apps use Spring Data Redis as before (P‑10).
- HA criteria and the upgrade path to Sentinel/ElastiCache: ARCH §6.3, unchanged.

## 7. Object storage

- **Garage** ([ADR 0010](../adr/261020-use-garage-for-object-storage.md)) as the in‑cluster S3‑compatible store: 3 nodes as a StatefulSet, replication factor 3, PVC 20Gi each. If the cluster already runs Rook/Ceph, use Ceph RGW instead and skip Garage.
- Bucket `bookstore-covers`, private (no anonymous read; covers are served through inventory, ARCH §3.1).
- Key `inventory-covers` with read/write on that bucket only; credentials in Secret `s3-inventory`.
- Garage's region name (`garage` by default) → inventory `S3_REGION`; `S3_PATH_STYLE=true`.
- Backup: nightly `rclone sync` CronJob of `bookstore-covers` to the off‑cluster backup bucket (P‑05).
- AWS phase 2: switch to Amazon S3 by changing `S3_ENDPOINT` (unset), `S3_PATH_STYLE=false` and credentials (IRSA/Pod Identity) in the `aws` overlay.

## 8. Namespaces and NetworkPolicies

Every namespace gets a default‑deny (ingress and egress) policy plus DNS egress. Then allow exactly ARCH §2's arrows (ARCH §6.2 rule 5):

| From | To | Port |
| --- | --- | --- |
| ingress controller | `bookstore-app/gateway` | 8080 |
| ingress controller | `identity/keycloak` | 8080 |
| `gateway` | `web` (SSR) | 4000 |
| `web` | `gateway` | 8080 |
| `gateway` | `inventory`, `user` | 8080 |
| `gateway` | `bookstore-data/redis-sessions` | 6379 |
| `gateway` | `identity/keycloak` | 8080 |
| `gateway` | public Keycloak host via ingress (OIDC discovery, 01 G‑03) | 443 |
| `keycloak` | `bookstore-app/gateway` (back‑channel logout) | 8080 |
| `inventory` | `bookstore-data/pg-main` | 5432 |
| `inventory` | `bookstore-data/rabbitmq` | 5672 |
| `inventory` | `bookstore-data/redis-cache` | 6379 |
| `inventory` | `bookstore-data/garage` | 3900 |
| `inventory`, `user` | `identity/keycloak` | 8080 |
| `user` | `bookstore-data/users-rs0` | 27017 |
| `keycloak` | `bookstore-data/pg-main` | 5432 |
| `keycloak` | SMTP relay | 587 |
| `bookstore-app/*`, `identity/*` | `observability/otel-collector` | 4317 |
| `observability/prometheus` | all management/metrics ports | 8081, 9000, 9187, 9216, 15692, 9121, 9464 |
| backup jobs / CNPG / PBM | off‑cluster backup endpoint | 443 |

Plus intra‑cluster replication traffic for each stateful set (CNPG instances, Mongo members, RabbitMQ nodes, Garage nodes, Keycloak Infinispan).

Database‑level isolation (only inventory reaches the `inventory` DB) is enforced by credentials and `REVOKE CONNECT` (§3.2), since NetworkPolicy works at pod/port level and both inventory and Keycloak legitimately reach port 5432.

```

├── charts/
│   ├── gateway/  inventory/  user/  web/          # app charts (each doc §8)
```

Overlay values per environment: hostnames, `STORAGE_CLASS_FAST`, replica counts, resources, `ClusterSecretStore` name, backup endpoint. Nothing else differs (ARCH §6.2 rule 3).

Argo CD sync waves:

| Wave | What |
| --- | --- |
| −2 | Namespaces, NetworkPolicies, ExternalSecrets |
| −1 | `data` chart (PostgreSQL, MongoDB, RabbitMQ, Garage), both Redis releases |
| 0 | Keycloak CR |
| 1 | keycloak-config-cli Job (PostSync hook of the Keycloak app) |
| 2 | inventory, user |

Health checks: add Argo CD custom health Lua for `Cluster` (CNPG), `PerconaServerMongoDB`, `RabbitmqCluster` and `Keycloak` if your Argo CD version lacks built‑ins, so waves actually wait for readiness.

Image tags for app charts are set by CI (commit SHA) in the environment overlay via a PR (P‑13).

## 11. Observability (data tier)

| Component | Metrics source | Key alerts |
| --- | --- | --- |
| PostgreSQL | CNPG PodMonitor (9187) | replication lag > 30 s (ARCH §6.4), instance down, WAL archiving failing, backup older than 26 h, disk > 80 % |
| MongoDB | Percona exporter (9216) | member not healthy, replication lag > 30 s, PBM backup failed |
| RabbitMQ | `rabbitmq_prometheus` (15692) | memory/disk alarm, node down, `catalog.*.dlq` messages > 0 (ARCH §6.4 "dead‑letter queue non‑empty"), queue depth growing for 10 min |
| Redis | redis_exporter (9121) | down; `redis-sessions` memory > 80 % of maxmemory (noeviction would start rejecting writes); `redis-cache` evictions rate (info), AOF rewrite failure |
| Garage | built‑in metrics endpoint | node down, disk > 80 % |

Grafana dashboards: import the upstream dashboards for CNPG, RabbitMQ, Redis exporter and Percona MongoDB; commit them as ConfigMaps (`grafana_dashboard: "1"` label).

## 12. Failure modes

| Failure | Behaviour |
| --- | --- |
| Node loss | Each stateful set spreads across nodes; CNPG/Mongo/RabbitMQ fail over; single‑instance Redis is rescheduled (ARCH §6.3 accepted impact) |
| StorageClass outage | Everything stateful stops; restore from off‑cluster backups |
| Backup target unreachable | Alerts on archiving/backup age; no service impact |

## 13. Testing

- `helm template` + `kubeconform` for every chart and overlay in CI.
- `kind`‑based integration job: install operators, sync `onprem/dev`, wait for all waves healthy, run each service's smoke test and the Playwright e2e suite (04 §11).
- NetworkPolicy test: from a debug pod in `bookstore-app` labelled as `user`, connecting to `pg-main:5432` must time out; labelled as `inventory`, must succeed.
- Restore drills (§3.3), recorded with date and measured RTO.
